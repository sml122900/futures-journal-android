## 작업 내용

### futures-journal-android — Android Emergency Brake 앱 초기 구현

**목표:** 비트겟 모바일 앱 위에 강제 오버레이 경고를 표시하는 Android 앱 (A1~A10 전 단계)

---

#### A1 — 프로젝트 설정 + 의존성
- AGP 9.2.1 / Kotlin 2.2.10 기반 프로젝트에 Firebase, Retrofit, OkHttp, Moshi, Security-Crypto 추가
- `gradle/libs.versions.toml` 버전 카탈로그 방식으로 통일
- google-services 플러그인 연결

#### A2 — Manifest + 기본 구조
- `SYSTEM_ALERT_WINDOW`, `POST_NOTIFICATIONS`, `FOREGROUND_SERVICE` 등 권한 선언
- `FuturesJournalApp`, `SplashActivity`, `LoginActivity`, `OnboardingActivity`, `SettingsActivity` 스텁 생성
- `FcmService`, `OverlayService` 서비스 선언

#### A3 — Firebase Cloud Messaging
- `FcmService.onMessageReceived` 구현 — FCM 수신 시 EmergencyPayload 파싱 후 OverlayService 시작
- `EmergencyPayload` Serializable 데이터 클래스 (Parcelize 플러그인 충돌로 Serializable 대체)
- `ApiClient` Retrofit 스텁

#### A4 + A5 — OverlayService + 경고 UI
- `WindowManager.TYPE_APPLICATION_OVERLAY`로 다른 앱 위 풀스크린 오버레이 표시
- `overlay_warning.xml` XML 레이아웃 (카운트다운, 강제 타이핑, 비트겟 이동 버튼)
- Level 1/2/3 drawable 배경색 (노랑/주황/빨강)
- Foreground 서비스 알림, 화면 깨우기, Level 3 진동+소리

#### A6 — 타이핑 검증 강화
- `overlayStartTime` 추적 → `durationSeconds` 서버 전송

#### A7 — 로그인 + 토큰 관리
- `TokenStore`: EncryptedSharedPreferences (AES256-GCM)
- `ApiClient`: Retrofit + MoshiConverterFactory 완성, Bearer 토큰 인증
- `LoginActivity`: 토큰 입력 → 서버 검증 → FCM 토큰 등록
- `SplashActivity`: 인증/온보딩 상태에 따른 라우팅

#### A8 — 권한 안내 온보딩
- `PermissionHelper`: 오버레이/알림/배터리 최적화 권한 체크 + 요청
- 제조사별 추가 안내 (샤오미/화웨이/OPPO)
- `OnboardingActivity`: 3단계 권한 순서 안내

#### A9 — 메인 서버 통합 (futures-journal)
- `prisma/schema.prisma`: `DeviceRegistration` 모델 + `User.androidAuthToken` 필드 추가
- `npx prisma db push` 실행 → DB 반영 완료
- `src/lib/fcm-sender.ts`: Firebase Admin SDK FCM 발송
- API 라우트 7개: `/api/devices/*`, `/api/users/me`, `/api/users/android-token`, `/api/emergency/cancel`, `/api/emergency/proceed`
- `emergency-scheduler.ts`: 텔레그램 발송에 FCM 발송 추가 (level ≥ 2)
- Firebase 서비스 계정 키 → `.env` 저장

#### A10 — 빌드
- `app/build.gradle.kts` signingConfigs 구조 추가 (주석 처리, 환경변수 방식)
- `assembleDebug` → `app-debug.apk` 생성 확인

## 트러블슈팅

| 문제 | 원인 | 해결 |
|------|------|------|
| `kotlin.android` 플러그인 충돌 | AGP 9.x가 자동 적용, 중복 등록 에러 | `kotlin.android` 제거, `kotlin.compose`만 유지 |
| `kotlinOptions` 미인식 | `kotlin.android` 없으면 사용 불가 | 블록 제거 (AGP가 `compileOptions`에서 자동 추론) |
| `@Parcelize` 미동작 | `kotlin-parcelize` 플러그인 적용 후에도 `kotlinx.parcelize` 미인식 | `Parcelable` → `Serializable`로 대체 |
| `android:hintTextColor` 오류 | 존재하지 않는 속성명 | `android:textColorHint`로 수정 |
| `prisma migrate dev` 비대화형 오류 | 대화형 전용 명령 | `prisma db push --accept-data-loss` 사용 |

### 실기기 테스트 및 FCM 버그 수정

**목표:** Galaxy S26에서 FCM → 오버레이 E2E 검증 및 발견된 버그 수정

---

#### 실기기 연결 및 APK 설치
- `adb install app-debug.apk` 로 Galaxy S26에 설치 성공
- adb PATH 미설정 문제 → 절대 경로 `AppData/Local/Android/Sdk/platform-tools/adb.exe` 로 해결

#### Android 토큰 발급 UI 추가 (futures-journal 서버)
- `/settings/notifications` 페이지에 "Android 앱 연동" 섹션 추가
- GET `/api/users/android-token` → 토큰 표시 + 복사 버튼
- POST `/api/users/android-token` → 재발급 (confirm 확인)
- A9 서버 파일들이 커밋되지 않은 채로 남아있던 것 발견 → 일괄 커밋/푸쉬

#### FCM 버그 수정 — onMessageReceived 미호출 문제
- **문제:** FCM은 수신되는데 OverlayService가 시작되지 않음
- **adb logcat 분석:** `"Notification Channel requested (emergency) has not been created"` → 시스템이 알림을 직접 처리 중
- **원인:** `fcm-sender.ts`에서 `data`와 `android.notification`을 함께 발송 → 앱 백그라운드 시 시스템이 `onMessageReceived` 건너뜀
- **수정:** `android.notification` 블록 제거 → 순수 data message로 변경
- FCM 테스트 엔드포인트 `/api/test/fcm` 추가 (임시, POST)

#### 오버레이 UI 전면 개편
- **카운트다운:** 120sp 대형 숫자, 매 초 1.3배 펄스 + 노랑→주황→빨강 색상 변화, 버튼 없음
- **타이핑 완료 흐름:** "본인과의 약속을 지키십시오." + "확인" 버튼 → 오버레이 종료
- **OverlayPrefs:** SharedPreferences 기반 설정 저장소 (선택 멘트, 커스텀 멘트, 카운트다운 시간)
- **기본 멘트 13개** 사전 정의, 기본 선택: "나는 충동이 아닌 원칙으로 매매할 것을 맹세한다"

#### SettingsActivity 완전 구현
- 카운트다운 시간 설정 (최소 5초)
- 현재 선택 멘트 표시 + "멘트 목록" 버튼
- 멘트 목록 다이얼로그: 탭으로 선택, 삭제 버튼 (기본/커스텀 모두)
- "커스텀 멘트 추가" → 중첩 다이얼로그 입력
- 기본 멘트 삭제: `hidden_defaults` Set으로 관리 (앱 재설치 시 복원 가능)
- 상단 상태바 겹침 수정: `fitsSystemWindows="true"` + 커스텀 타이틀바
